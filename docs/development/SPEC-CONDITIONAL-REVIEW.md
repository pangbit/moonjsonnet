## Exact judgments and completion boundary

[chk-if](https://github.com/google/jsonnet/blob/bbb38f1020be1f5aed560928fb839b2c448cefb4/doc/ref/spec.html#static_checking)
at lines 1666-1670 requires all three children to check in the same Gamma.
It introduces no binder and contains no Boolean-type or evaluation premise.
Consequently an undefined child rejects even in an unselected branch or an
entirely unused conditional, and a child's own local binder cannot escape into
a sibling. Object-context permission must be passed unchanged to every child.

[if-true and if-false](https://github.com/google/jsonnet/blob/bbb38f1020be1f5aed560928fb839b2c448cefb4/doc/ref/spec.html#execution)
at lines 2273-2287 require the condition to yield the corresponding Boolean and
only the selected child to yield v. The unselected child is absent from their
evaluation premises. The conditional must return that value in the existing
lexical/object environment, including when v is a function or a lazy container.
Non-Booleans satisfy neither rule. The operational-semantics introduction models
both explicit and implicit runtime failures as stuck execution.

These are constructor-transfer judgments relative to their child judgments.
Completion of a constructor rule requires exact case analysis of how it invokes
the child checker/evaluator, unchanged environment transfer, and executed positive,
negative and demand controls through source and independently handmade ASTs.
It does not certify all possible child expressions, every other rule, compiler
correctness, manifestation or unbounded host resources. This is an engineering
review rather than a machine-checked proof of the whole interpreter.

## Independent necessary conditions

| Rule / boundary | Predefined expected behavior |
| --- | --- |
| chk-if, all three positions | A lone undefined condition/then/else child rejects Static through source and handmade AST, including unused conditional wrappers; valid surrounding Gamma is retained in every position |
| chk-if, context and isolation | self/super reject outside object context in all three positions; valid inherited self/super condition/branch expressions retain context. Child-local names cannot leak between siblings |
| Source grammar | Missing condition/then-token/branch expressions reject Syntax before a Program exists; typed ASTs do not represent malformed source text |
| Both evaluation rules | Native event logs are exactly condition,selected-branch for true and false; an unused conditional invokes neither condition nor branch |
| Condition type | Null, number, string, array, object and function conditions reject before either branch callback; nested array/object/function payload callbacks remain unused |
| Failure timing | A failing condition callback records only condition; a selected failing branch records condition,selected-branch and propagates failure; the other branch is never demanded |
| Value preservation | Both choices retain independently specified null/Boolean/number/string/array/object values. A selected function is called afterward once, without eager body execution or demanding the unused branch |
| Environment preservation | A local in the condition does not replace an outer binding seen by the selected child; inherited self/super are retained through branch selection |

Expected scalar/container outputs, event sequences and error roles are written
directly, not generated by the implementation, parser round trips or Go/C++.
Public Static/Syntax/Type/Runtime categories distinguish embedding phases; the
fixed inference rules do not mandate their exact diagnostic wording/locations.
Each rejecting static probe isolates one invalid child, so no diagnostic priority
between several simultaneous static errors is invented.

## Reused evidence and explicit exclusions

Existing A1 and AP6 already reject invalid handmade/source dead branches; IU3
already checks a false source/handmade branch avoids a virtual import request.
Their relevant assertion meanings will be mapped and reused, not counted as new
tests. Existing ordinary function/default and object/substitution controls remain
controls rather than new completion of their respective rules.

The source parser and handmade AST creation are distinct entry paths. Syntax is
source-only; Static is before Program creation; runtime type/error checks happen
after successful creation. All fixtures/callbacks are self-made and perform no
actual imported-file, private-document or network I/O. Resource-limit and stack
exhaustion, diagnostic trace formatting, complete surface/desugaring grammar,
full child/binder/object algebra and CLI exit rendering are separate obligations.
No error/unary rule review, CLI/reference/platform/remote/full-suite campaign is
included. The preceding 491/491 macOS integration and 66+1 debug CLI evidence
remain attached to cd5ea7b; no later source inherits those results automatically.
